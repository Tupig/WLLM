# Unity MMORPG 自动化测试平台 - 说明文档

本文档说明平台功能、安装运行、API 及 Agent 使用。技术栈与架构见 **技术方案.md**（同目录）。

---

## 一、功能说明

### 1.1 编排服务

- **任务队列**：按平台（windows / mac / linux / **web** / android / ios）创建任务，可指定 **required_skills**，仅具备该技能的 Agent 拉取并执行。
- **Skills**：集成测试能力，含 **Unity**（PlayMode、EditMode、AltTester）、**Web**（WebChrome、WebFirefox、Playwright、Selenium、Cypress、WebHeadless 等，支持测试所有 Web）、**Mobile**（ADB、XCUITest、Appium、Airtest、Poco）、**AI**（AIAgent）。Agent 注册时声明，任务可指定所需。
- **Agent 管理**：注册（含 skills）、心跳、列表；支持多台执行机、多环境。
- **结果收集**：Agent 上报通过/失败、日志路径、摘要；结果存于内存并落盘 `data/runs/`。
- **Web 看板**：查看 Agent 列表、任务列表、创建任务。

### 1.2 Agent

- 各环境一个 runner 脚本（Mac / Linux / Windows / **Web** / Android / iOS），循环：心跳 → 拉取该平台任务（按 skills 匹配）→ 执行（占位可替换为真实 Unity/ADB/浏览器 调用）→ 上报结果。**Web** 使用 `runner_web.py`，支持多浏览器与 Playwright/Selenium 等，可测试所有 Web。
- **可选集成任务**：Windows / Android runner 按 `extra.job_type` 自动分发两类集成任务——`airtest`（Airtest 图像识别脚本）与 `ai_exploratory`（AI 探索测试），依赖 `pip install -r requirements-airtest.txt`，详见 **docs/Airtest与AI探索测试集成方案.md**。
- 环境变量：`PLATFORM_URL`、`AGENT_ID`、`PLATFORM`、`AGENT_SKILLS`（可选，逗号分隔，如 `PlayMode,EditMode`）。

### 1.3 与 Unity / CI 的关系

- **Unity 项目**：使用 Unity Test Framework（NUnit），Play Mode / Edit Mode；可选 AltTester。
- **CI**：可将 GameCI 示例（`.github/workflows/unity-test.example.yml`）复制到 Unity 项目仓库，在 GitHub Actions 中多平台构建与测试；本平台可独立作为调度中心，由 CI 或人工触发任务，Agent 在各环境执行。

### 1.4 Rust + Go 版本（v2，推荐）

- **编排服务（Go，`server/`）**：仅标准库、单二进制；API 与本文档完全一致，兼容现有 `data/` 目录与 `static/` 看板。运行 `cd server && go run .`（或 `go build -o unity-orchestrator .`）；`PORT`/`DATA_DIR`/`STATIC_DIR` 环境变量或 `-port`/`-data`/`-static` 参数可覆盖默认值。
- **Agent（Rust，`agent/`）**：`cargo build --release` 产出 `target/release/unity-agent`；环境变量与 Python Agent 一致（`PLATFORM_URL`、`AGENT_ID`、`PLATFORM`、`AGENT_SKILLS`，另有 `AGENT_WORKDIR` 指定产物目录）。AI 探索测试在 Android 上为原生实现（adb 截图/操作 + OpenAI 兼容视觉接口），目标机无需 Python；`airtest` 任务仍调用 airtest CLI（可选安装）。
- Python 版保留为 legacy；API、看板、`data/` 文件格式三端一致，可混用。

## 二、环境与依赖

### 2.1 编排服务

- **系统**：Mac / Linux / Windows。
- **Python**：3.10+。
- **依赖**：`fastapi`、`uvicorn`、`pydantic`（见 `requirements.txt`），`pip install -r requirements.txt` 默认安装。

### 2.2 Agent 执行机

- **Windows / Mac / Linux**：需安装 Unity（Editor 或仅 Player），以便执行 Test Framework 或已构建测试包。
- **Linux 无头**：可用 `xvfb-run` + Unity `-batchmode -nographics`。
- **Android**：需 ADB、模拟器或真机。
- **iOS**：需 Mac、Xcode、模拟器或真机。
- **可选集成**（Airtest / AI 探索测试，Android/Windows Agent）：`pip install -r requirements-airtest.txt`；AI 探索另需 `OPENAI_API_KEY`（视觉模型用 `OPENAI_VISION_MODEL` 单独指定，支持 `OPENAI_BASE_URL` 自定义兼容接口）。

## 三、安装与运行（Mac）

### 3.1 编排服务（Linux / Windows / Mac）

**源码运行**  
- Mac / Linux：`./scripts/run.sh` 或 `python3 -m venv .venv && source .venv/bin/activate && pip install -r requirements.txt && python run_server.py`  
- Windows：执行 `scripts\run.bat`  

**构建可执行文件后运行（目标机无需安装 Python）**  
- Mac / Linux：在项目根目录执行 `./scripts/build.sh`，运行 `./dist/unity-test-platform`  
- Windows：在项目根目录执行 `scripts\build.bat`，运行 `dist\unity-test-platform.exe`  

数据目录 `data/` 在可执行文件同目录下自动创建。端口固定为 9111。

### 3.2 Agent（示例：Mac）

```bash
export PLATFORM_URL=http://localhost:9111
export AGENT_ID=agent-mac-1
export PLATFORM=mac
export AGENT_SKILLS=PlayMode,EditMode
python3 agents/runner_mac.py
```

其他环境：替换为 `runner_linux.py`、`runner_windows.py`、`runner_android.py`、`runner_ios.py`，并设置 `PLATFORM=linux|windows|android|ios`。

### 3.3 看板

浏览器打开 **http://localhost:9111**：查看 Agent、任务、创建任务。

## 四、API 说明

### 4.1 Skills

- **GET /api/skills**  
  响应：`{ "items": [{ "id": "PlayMode", "name": "Unity PlayMode", "description": "...", "platforms": [...] }], "total": N }`

### 4.2 Agent

- **POST /api/agents/register**  
  请求体：`{ "agent_id": "xxx", "platform": "mac", "skills": ["PlayMode", "EditMode"], "extra": {} }`  
  响应：`{ "ok": true, "agent_id": "xxx" }`

- **POST /api/agents/heartbeat**  
  请求体：`{ "agent_id": "xxx", "status": "idle|running", "current_job_id": 1 }`  
  响应：`{ "ok": true }`

- **GET /api/agents**  
  响应：`{ "items": [...], "total": N }`

### 4.3 任务

- **POST /api/jobs**  
  请求体：`{ "platform": "mac", "required_skills": ["PlayMode"], "unity_project_path": "/path", "test_filter": "xxx", "extra": {} }`  
  响应：`{ "ok": true, "job_id": 1 }`  
  **Web 任务**：`platform: "web"`，`required_skills` 如 `["Playwright", "WebChrome"]`，`extra` 可传 `{ "url": "https://...", "browser": "chromium", "headless": true }` 供 Web Agent 使用。  
  **GPT 生成并执行**：`extra` 传 `{ "job_type": "generate_and_run", "prompt": "主界面点击设置应打开设置面板" }`，编排服务会调用 GPT 生成 C# 测试代码并写入 `extra.generated_test_csharp`，需配置 OPENAI_API_KEY 与 `pip install openai`；详见 **docs/GPT生成测试用例集成方案.md**。  
  **Airtest 任务**：`extra` 传 `{ "job_type": "airtest", "script_path": "/opt/scripts/login.air", "device_serial": "emulator-5554" }`，由具备 `Airtest` 技能的 Agent 运行 .air 图像识别脚本（Android/Windows）。  
  **AI 探索测试**：`extra` 传 `{ "job_type": "ai_exploratory", "prompt": "登录游戏并打开设置面板", "max_steps": 15 }`，Agent 截图交由视觉大模型决策并循环操作设备；需 `pip install -r requirements-airtest.txt` 与 OPENAI_API_KEY。任务协议与动作空间详见 **docs/Airtest与AI探索测试集成方案.md**。

- **POST /api/generate-test**（可选）  
  请求体：`{ "prompt": "自然语言测试需求", "assembly": "Assembly-CSharp" }`  
  响应：`{ "code": "C# 测试代码", "error": null }` 或 `{ "code": null, "error": "未配置 OPENAI_API_KEY" }`。需 `pip install openai` 与 OPENAI_API_KEY。

- **GET /api/jobs**  
  响应：`{ "items": [...], "total": N }`

- **GET /api/jobs/{job_id}**  
  响应：单条任务（含 result）。

- **GET /api/jobs/poll/{platform}?skills=PlayMode,EditMode**  
  Agent 拉取该平台下一条 pending 任务；可选 `skills` 逗号分隔，仅返回 required_skills 为 agent 技能子集的任务；若存在则置为 running 并返回。  
  响应：`{ "job": { ... } }` 或 `{ "job": null }`

- **POST /api/jobs/{id}/cancel**（v2）  
  取消任务：pending/running → cancelled（终态，Agent 迟到的结果不再覆盖；已通过/失败返回 409）。  
  响应：`{ "ok": true, "status": "cancelled" }`

- **DELETE /api/jobs/{id}**（v2）  
  删除任务（列表移除 + 快照文件删除）。响应：`{ "ok": true }`

- **POST /api/jobs/artifacts**（v2，Agent 上传执行记录）  
  请求体：`{ "job_id": 1, "agent_id": "xxx", "files": [{ "name": "steps.json", "content": "…" }] }`（≤10 个文件，请求体 ≤1MB）。  
  响应：`{ "ok": true, "stored": 1 }`

- **GET /api/jobs/artifacts?job_id=1** / **GET /api/jobs/artifacts/{name}?job_id=1**（v2）  
  查看任务执行记录列表 / 读取单个文件内容。AI 探索与 Airtest 任务执行后由 Agent 自动上传。

- **POST /api/jobs/result**  
  请求体：`{ "job_id": 1, "agent_id": "xxx", "success": true, "log_path": "/path", "summary": {} }`  
  响应：`{ "ok": true }`

## 六、常见问题

**Q：如何接入真实 Unity 测试？**  
A：在对应 `agents/runner_*.py` 的 `run_unity_test(job)` 中调用 Unity 命令行（如 `Unity -batchmode -projectPath ... -runTests ...`）或已构建的 Player，根据 `job` 中的 `unity_project_path`、`test_filter` 等拼参数。

**Q：Linux 无显示器如何跑？**  
A：使用 `xvfb-run -a python3 agents/runner_linux.py`，或 Unity 使用 `-batchmode -nographics`。

**Q：Android / iOS 如何跑？**  
A：Android：本机/CI 需 ADB 与模拟器或真机，在 `runner_android.py` 中实现安装 APK、启动、拉日志。iOS：需在 Mac 上运行 `runner_ios.py`，配合 Xcode/模拟器或真机。

**Q：任务结果存哪？**  
A：内存 + `data/runs/job_<id>.json`；后续可改为 SQLite/PostgreSQL。

**Q：如何运行 Airtest 脚本或 AI 探索测试？**  
A：Android/Windows Agent 执行 `pip install -r requirements-airtest.txt`，以 `AGENT_SKILLS=Airtest,AIAgent` 启动；创建任务时 `extra.job_type` 传 `airtest`（运行 .air 脚本）或 `ai_exploratory`（AI 探索测试，需 OPENAI_API_KEY）。协议与示例见 **docs/Airtest与AI探索测试集成方案.md**。

更多约定见 **规则文档.md**（同目录）。
